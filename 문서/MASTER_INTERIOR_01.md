# MASTER_INTERIOR_01

인테리어·리모델링·집수리·시공 업체에 **반복해서 파는** 원페이지 마스터 템플릿.
고객 데이터만 갈아 끼우면 다른 업체 홈페이지가 된다.

```
python -m factory.cli build examples/master-interior-01.json -o out/gonggan --offline
python -m factory.cli serve out/gonggan
```

## 1. 레퍼런스 분석 (2026-09-28, 실제 접속)

네트워크가 열려 세 곳을 실제로 열어 재었습니다. **소스·문구·이미지는 가져오지 않았고,
치수와 구조만** 보았습니다.

| | dosodosi.com | cleanroum.com | inpe.kr |
| --- | --- | --- | --- |
| 첫 화면 제목 | 이미지·큰 블록 처리 (h1 19px) | 45px / 굵기 400 / 행간 1.29 | **72px / 굵기 900** / 행간 1.25 |
| 본문 | – | 16px / 행간 1.5 | 16px |
| 콘텐츠 폭 | – | 1320 | 1280–1420 |
| 섹션 상하 여백 | 112 → 80 반복 (히어로 202/173) | 80 · 72 · 96 | 80 · 96 · 112 · **144** |
| 카드 | 빌더 기본 (radius 4) | radius 24 + 부드러운 파란 그림자 | radius 0 + 큰 그림자 |
| 포인트 색 | 부트스트랩 기본값 그대로 | 파랑 계열 | **#ff5500 한 색을 277회** |
| 전환 장치 | 모바일 하단 고정 바 4칸(118px) + "10초 견적받기" 3회 반복 | 모바일 하단 고정 바 4칸(125px) | **데스크톱 오른쪽 세로 레일 6칸** |
| 신뢰 | 4가지 핵심 가치 블록 | 인증·후기 | 후기 흐름 + 다크 숫자 밴드(만족도·누적 건수) |
| 페이지 길이 | 5,241px | 7,865px | 28,518px |

읽어 낸 원칙과 우리가 한 것:

1. **첫 화면 제목은 크다.** 72px 급. → 우리 상한을 57.6 → **68px** 로 올렸습니다.
2. **여백은 80–144px.** → 우리 `clamp(72, 8.5vw, 132)` 는 그 범위 안. 그대로 둡니다.
3. **포인트 색은 하나만, 대신 자주.** → 이미 그렇게 하고 있었습니다(강조색 1개).
4. **문의 수단은 늘 화면에 붙어 있다.** 셋 다 고정 바나 레일을 씁니다.
   → 모바일 하단 바에 **아이콘**을 넣고, 넓은 화면에는 **오른쪽 세로 레일**을 더했습니다.
5. **사진 위 버튼은 흰색이나 포인트색.** → 우리 주 버튼이 차콜이라 어두운 사진 위에서
   묻히고 있었습니다. **흰 버튼 + 흰 테두리 보조 버튼**으로 바꿨습니다.
6. **후기에 사람이 보인다.** 아바타 원과 별점. → 머리글자 원을 넣었습니다.

셋 중 inpe.kr 이 가장 완성도가 높았고, 나머지 둘은 빌더(pagekr + 부트스트랩) 기반이라
카드·모서리·색이 기본값에 가까웠습니다. 우리 마스터는 이미 그 둘보다 정돈돼 있고,
inpe.kr 과 견줄 수 있는 수준을 목표로 위 여섯 가지를 고쳤습니다.

## 2. 디자인 방향

키워드는 modern · premium · clean · spacious · trustworthy · image-driven.

- **사진이 주인공.** 글은 큰 제목 + 짧은 설명까지. 카드 안에 문단을 쌓지 않는다.
- **여백이 값이다.** 섹션 상하 여백 `clamp(72px, 8.5vw, 132px)`. 좁은 화면에서 자동으로 줄어든다.
- **포인트 색은 하나.** 강조색은 숫자·라벨·점·별점에만 쓴다. 버튼은 주색 하나로 통일한다.
- **효과는 절제한다.** 카드가 4px 뜨고 사진이 4% 확대되는 정도. 자동 재생·시차 스크롤 없음.
- **글자 대비를 지킨다.** 본문 7:1, 흐린 글씨·버튼 글자 4.5:1. 시험이 네 테마 전부를 검사한다.
- 자간은 한글에 맞춘다(`-0.032em`). 영문 라벨(SERVICES 등)만 자간을 벌린다.

## 3. 섹션 구성

요청받은 흐름을 따르되 **유도 띠를 한 번 더** 넣었다. 시공 사례를 보고 마음이
움직인 사람이 절차·후기·FAQ 를 다 지나 맨 아래까지 가야 연락할 수 있으면 놓친다.

```
HEADER
 1 HERO          핵심 메시지 · 대표 사진 · 견적/카카오톡 · 신뢰 뱃지
 2 STRENGTHS     숫자 4개 (히어로에 물리는 흰 카드 띠)
 3 SERVICES      시공 범위 — 사진 카드
 4 ABOUT         일하는 방식 + 표 + 대표 서명
 5 PROJECTS      시공 사례 — 분류 칩 · 큰 격자 · 크게 보기
 6 CTA           중간 유도 띠 (전화 · 카카오톡 · 견적)
 7 PROCESS       상담 → A/S 까지 번호와 기간
 8 REVIEWS       별점 · 공사 이름
 9 FAQ           접히는 목록
10 CONTACT       견적 폼 + 연락처 + 지도 (최종 CTA)
FOOTER + 모바일 하단 고정 바
```

재료가 없는 섹션은 **뺀다**. 사진이 없으면 시공 사례 섹션이 통째로 빠지고 메뉴에서도
사라진다. 빈 껍데기를 팔지 않기 위해서다.

## 4. 고객 데이터 구조

주문서 한 장(JSON/YAML)이 곧 `siteConfig` 다. 한글 키를 그대로 쓸 수 있다.

```jsonc
{
  "template": "master-interior-01",     // 관리자 웹의 "템플릿 선택"
  "company":  { "name", "industry", "tagline", "description", "founded", "owner" },
  "hero":     { "headline", "subline", "image", "badges[]", "cta_label" },
  "strengths":[ { "name", "number", "unit", "summary" } ],
  "services": [ { "name", "설명", "사진", "항목[]", "가격" } ],
  "about":    { "heading", "paragraphs[]", "image", "facts[{label,value}]", "signature" },
  "projects": [ { "name", "분류", "위치", "평형", "연도", "설명", "사진", "추가사진[]" } ],
  "process":  [ { "name", "설명", "기간" } ],
  "reviews":  [ { "내용", "이름", "시공", "별점" } ],
  "faq":      [ { "질문", "답" } ],
  "contact":  { "전화", "카카오톡", "이메일", "주소", "영업시간", "지도", "링크{}" },
  "site":     { "pages", "domain", "goals[]", "features[]", "primary_cta" },
  "theme":    "charcoal",               // 또는 { preset, primary, accent, background, surface, mode, radius, font }
  "seo":      { "title", "description", "지역명", "공유이미지", "favicon", "keywords[]" }
}
```

디자인 코드에는 업체 정보가 한 글자도 들어 있지 않다. 템플릿은 위 칸을 읽을 뿐이다.

### 새 고객 홈페이지를 만들 때 바꾸는 것

1. `company` — 업체명·업종·한 줄 소개·소개글·설립·대표
2. `contact` — 전화·카카오톡·이메일·주소·영업시간·지도
3. `hero` — 대표 문구·서브 문구·대표 사진·뱃지
4. `strengths` · `services` · `projects` · `process` · `reviews` · `faq` — 개수 자유
5. 사진 파일 — `examples/photos/...` 자리에 고객 사진 경로만 넣으면 전부 교체된다
6. `theme` — charcoal / beige / black / green 중 하나 (또는 색 직접 지정)
7. `seo` — title·description·지역명·공유이미지·키워드
8. `brand.logo` — 로고 파일 (없으면 머리글자를 그려 넣는다)

**디자인 파일은 건드리지 않는다.** 한 줄도.

| `charcoal` (기본) | 차분하고 단단함 | `#2E3338` | `#A8763C` | 흰색 + 웜그레이 면 |

## 6. 기술 구조

이미 있는 공장 위에 얹었다. 새 의존성은 없다.

- **Python 3.11 + Jinja2** (+ YAML 주문서용 PyYAML). 빌드 도구·프레임워크·데이터베이스 없음
- 산출물은 **정적 파일**: HTML 한 장 + CSS 한 장 + 사진 + sitemap/robots/JSON-LD
- 자바스크립트는 4KB 남짓, 전부 **없어도 페이지가 도는** 것들만
  (머리 색 전환 · 모바일 메뉴 · 분류 칩 · 크게 보기)
- 호스팅: Netlify / Vercel / GitHub Pages / 일반 FTP — 설정 파일을 같이 내보낸다

컴포넌트는 `templates/master-interior-01/partials/` 안에 하나씩:
`header · hero · strengths · items(services) · about · projects · process ·
testimonials · faq · cta · contact · footer(+모바일바) · scripts`

## 7-1. 사진 최적화

`factory/images.py` 가 산출물로 옮기면서 역할에 맞는 크기로 줄이고 WebP 로 바꿉니다.
**원본 파일은 건드리지 않습니다.**

| 역할 | 최대 가로 |
| --- | --- |
| 히어로 | 1920 |
| 시공 사례 | 1600 |
| 소개·갤러리·공유이미지 | 1200 |
| 서비스 카드 | 900 |
| 썸네일 | 500 |
| 로고 | 400 |

- 휴대폰 EXIF 회전을 실제로 적용합니다(눕힌 사진이 그대로 나가지 않습니다)
- 작은 사진을 억지로 키우지 않습니다
- WebP 가 원본보다 크면 원본을 씁니다
- SVG·GIF 는 손대지 않습니다
- Pillow 가 없거나 파일이 깨졌으면 **조용히 넘어가지 않고** 원본을 복사한 뒤 경고를 남깁니다
- `--no-optimize` 로 끌 수 있습니다

4032×3024 사진 한 장 기준으로 역할별 1920/1600/900/500px WebP 가 나옵니다.
결과는 `build_report.json` 의 `images` 와 납품 메모에 적힙니다.

| 고객 A | 113KB | 43KB | 28KB | 34KB | 4.2KB |
| 고객 B | 101KB | 34KB | 28KB | 31KB | 4.2KB |

## 8. 앞으로 만들 관리자 웹과 어떻게 붙는가

지금 구조가 그대로 관리자 웹의 저장 형식이다.

```
관리자 웹 폼  ─┐
               ├─→ siteConfig(JSON) ─→ factory.pipeline.build() ─→ out/<고객>/ ─→ 배포
사진 업로드   ─┘                              ↑
                                    템플릿 선택 = siteConfig.template
```

- 폼 한 칸 = 데이터 한 칸. 위 4장의 구조를 그대로 입력 폼으로 펴면 된다.
- 미리보기는 `build()` 를 임시 폴더에 돌려 그 `index.html` 을 iframe 으로 띄우면 된다.
  빌드가 1초 안에 끝나므로 저장할 때마다 다시 그려도 된다.
- 사진 업로드는 파일을 저장한 뒤 경로만 데이터에 넣으면 된다.
  `_stage_assets()` 가 산출물 폴더로 알아서 복사한다.
- 발행은 산출물 폴더를 그대로 올리는 것이다(`--zip` 으로 묶어 넘겨도 된다).
- 도메인 연결은 `site.domain` 만 채우면 canonical·sitemap·og:image 절대주소·CNAME 이 따라온다.

이번 작업에서 만들지 않은 것: 관리자 웹, 로그인, 결제, CMS, 게시판, 백엔드.

## 9. 알고 있는 한계

- 시공 사례 상세 페이지는 없다(V1 계획대로). 원페이지 안의 크게 보기로 대신한다.
- 사진 최적화(webp 변환·크기 축소)는 하지 않는다. 고객이 준 파일을 그대로 복사한다.
- 견적 폼은 받는 곳이 없다. `--form-action` 으로 Formspree 같은 주소를 꽂아야 메일이 온다.
- 예시 사진은 이 저장소에서 직접 그린 SVG 다(`tools/make_placeholders.py`).
  비율을 일부러 섞어 두었다 — 16:9 · 4:3 · 1:1 · 3:4 가 한 격자에 섞여도 깨지지 않는지 보기 위해서.
