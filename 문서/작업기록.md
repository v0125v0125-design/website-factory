## 바꾸지 말 것

### 1. 지어내지 않는다

주문서에 없는 사실은 원고에 쓰지 않습니다. "20년 경력", "직접 볶은 원두" 같은 말은
고객이 적어 준 것이 아니면 절대 넣지 않습니다. **흐린 문장이 그대로 상품이 되어 나가기
때문**입니다. 재료가 없으면

- 섹션을 뺀다 (`content.py` 의 각 builder 가 `None` 을 돌려준다)
- 속장의 본체가 없으면 그 장 자체를 내지 않고 메뉴에서도 지운다
- 사람이 채울 자리는 `[한 줄 소개]` 처럼 남기고 `납품메모.md` 체크리스트에 올린다

머리말·버튼 글자처럼 사실 주장이 아닌 말만 업종에 맞춰 바꿉니다
(치과의 "서비스" → "진료 과목"). 이것은 `content.py` 의 `LEXICONS` 입니다.

### 2. 스타일이 정해지는 순서

```
주문서에 못 박은 값  →  레퍼런스에서 읽어 낸 값  →  업종 기본값
```

앞의 것이 있으면 뒤의 것을 쓰지 않습니다. **이 순서를 뒤집지 마십시오** —
고객이 지정한 색이 레퍼런스에 밀리면 항의가 들어옵니다.

### 3. 색은 만든 뒤 다시 잰다

본문 7:1, 흐린 글씨와 버튼 글자 4.5:1 (WCAG AA). `colorkit.py` 가 밝기를 옮겨
기준을 맞추고, `contrast_audit()` 가 결과를 보고서에 적습니다.
이 기준은 시험으로 잠겨 있습니다.

### 4. 레퍼런스에서 가져오는 것은 치수뿐

색·서체 이름·모서리 반경·여백만 봅니다. 문장·이미지·마크업은 가져오지 않습니다.
`reference.py` 는 **판단하지 않고 사실만 긁습니다.** 고르는 일은 `theming.py` 가 합니다.
이 경계를 흐리면 "왜 이 색인가"를 설명할 수 없게 됩니다.

## 이미 확인한 것 — 다시 하지 마십시오

실제로 지어 보고 브라우저로 확인해서 잡은 것들입니다. 시험으로 잠가 두었습니다.

- **JSON-LD 를 Jinja 자동 이스케이프에 태우면 안 된다.**
  `&#34;` 로 깨져 검색엔진이 못 읽습니다. `render.py` 에서 `Markup` 으로 감싸고
  `</` 만 막습니다. (`test_json_ld_is_valid_json`)

- **HSL 채도로 "무채색"을 판단하면 안 된다.**
  크림색 `#fffaf3` 의 HSL 채도는 **1.0** 입니다. 거의 흰색·거의 검정에서 채도가 치솟기
  때문입니다. `colorkit.chroma()` 를 쓰십시오. (`test_chroma_separates_cream_from_white`)

- **바탕색을 "가장 많이 쓰인 배경색"으로 고르면 안 된다.**
  `.hero` 와 `.btn` 이 같은 붉은색을 쓰면 그 붉은색이 1등이 됩니다.
  `reference.find_body_background()` 로 `body`/`html` 규칙을 따로 봅니다.
  (`test_page_background_prefers_body_rule`, `test_strong_colour_is_not_mistaken_for_a_background`)

- **중간 밝기 색은 흰 글자도 검은 글자도 4.5 를 못 넘긴다.**
  `#4c6ef5` 같은 파랑이 그렇습니다(4.32). `colorkit.button_safe()` 가 밝기를 조금 옮겨
  통과시키되, 바탕과의 대비 3:1 도 같이 지킵니다.
  (`test_every_preset_produces_readable_tokens` — 14종 전부 검사)

- **밝은 사진 위 히어로는 덮개가 옅으면 글자가 사라진다.**
  베이지색 사진에 흰 글자면 대비가 2:1 까지 떨어집니다. 글이 놓이는 아래쪽을
  0.80 까지 덮습니다. (`test_photo_overlay_is_dark_enough_at_the_text`)

- **어두운 사진 위에서 보조 버튼을 주색 글자로 두면 안 된다.**
  전화번호 버튼이 읽히지 않았습니다. `.hero--image .btn--ghost` 는 흰 글자입니다.

- **속장의 본체가 비면 장 자체를 빼야 한다.**
  사진이 없는데 갤러리 장을 내면 제목 띠와 유도 버튼만 남은 빈 페이지가 팔려 나갑니다.
  (`test_subpage_without_its_main_section_is_not_shipped`)

- **한글 주문서는 평평하게 적어 온다.**
  `business:` 블록 없이 최상단에 `상호`, `업종`, `소개` 를 씁니다.
  `intake.parse_brief` 의 `biz()` 가 최상단도 봅니다.

- **YAML 한 줄 사전(`{...}`)에 쉼표와 물음표를 그냥 쓰면 깨진다.**
  `{가격: 45,000원}` 의 쉼표, `{질문: 됩니까?}` 의 물음표가 문법 충돌을 냅니다.
  본보기 YAML 처럼 블록 형식으로 쓰거나 따옴표로 묶으십시오.

- **HSL 채도로는 면(surface) 색을 못 지킨다.** 글자는 바탕뿐 아니라 띠 배경에서도
  읽혀야 합니다. `build_palette` 가 바탕과 면 둘 다에서 대비를 잽니다.

- **매개변수 이름을 함수 안에서 다시 계산하지 마라.** `build_palette(surface=...)` 가
  아래 분기에서 같은 이름을 덮어써 테마 면 색이 조용히 무시됐습니다.
  받은 값은 먼저 다른 이름으로 붙잡아 둡니다.

- **StrictUndefined 를 쓰므로 조각에서 없을 수 있는 칸은 `data.get('x')` 로 꺼낸다.**
  `data.image_placeholder` 처럼 쓰면 사진이 있는 고객에서 빌드가 멈춥니다.

- **`<img src="">` 를 두지 마라.** 브라우저가 현재 주소를 다시 받아와 깨진 이미지가 됩니다.
  크게 보기처럼 나중에 채우는 그림은 src 를 아예 비워 둡니다.

- **소개 표를 주면 자동 표를 덧붙이지 마라.** 설립·대표가 두 번 나왔습니다.
  고객이 준 것이 있으면 그것만 씁니다.

- **한글에 영문용 자간·대문자 변환을 걸지 마라.** `letter-spacing:.18em` + uppercase 는
  "공 간 인 테 리 어" 가 됩니다. 영문 라벨에만 겁니다.

- **어두운 사진 위에 테마 주색 버튼을 놓지 마라.** 차콜 주색이 어두운 히어로에서
  사라졌습니다. 사진 위 버튼은 테마와 무관하게 흰색/흰 테두리로 고정합니다.

- **HSL 채도가 아니라 chroma 를 보라** (1차에서 배운 것) — 그리고 **매개변수 이름을
  함수 안에서 다시 계산하지 마라**. `build_palette(surface=...)` 가 조용히 무시됐습니다.

- **지연 로딩 사진은 끝까지 스크롤한 뒤에 세어야 한다.** 브라우저 검사에서
  `complete === false` 를 깨진 사진으로 잘못 셌습니다.

- **`<img src="">` 를 두지 마라** — 브라우저가 현재 주소를 다시 받습니다.

- **소개 표를 주면 자동 표를 덧붙이지 마라.** 설립·대표가 두 번 나왔습니다.

- **검증기는 규격 이름과 엔진 내부 이름을 함께 알아야 한다.**
  `company`→`business`, `services`→`items`, `reviews`→`testimonials`.
  이걸 빼먹어 멀쩡한 예시가 전부 오류로 잡혔습니다.

- **메뉴 항목이 넘치면 머리가 두 줄로 접힌다.** 넓은 화면에는 5개까지만 내보내고
  나머지는 좁은 화면 메뉴에서만 펼칩니다. 시험이 두 줄을 잡습니다.

## 새 컴퓨터에서 이어서 하기

```bash
git clone https://github.com/v0125v0125-design/website-factory
cd website-factory
pip install -r requirements-dev.txt

python -m pytest -q                       # 175개가 통과하면 준비 끝
python -m factory.cli build examples/cafe-onepage.json -o out/bloom --offline --clean
python -m factory.cli serve out/bloom     # http://127.0.0.1:8765
```

필요한 것은 파이썬 3.11 이상과 Jinja2·PyYAML 뿐입니다. 데이터베이스도, 빌드 도구도,
API 키도 쓰지 않습니다. 인터넷은 레퍼런스를 볼 때만 필요하고, 없으면 `--offline` 로
업종 기본값으로 짓습니다.

Claude Code 로 이어서 작업하실 때는 세션을 시작하며 저장소로 **website-factory** 를
고르십시오. 그러면 `CLAUDE.md` 와 이 파일이 자동으로 읽힙니다.

## 파는 순서 (실제 업무 흐름)

1. **받기** — 고객에게 상호·업종·연락처·소개·메뉴/서비스·사진·레퍼런스 주소를 받습니다.
   `examples/salon-onepage.yaml` 을 그대로 복사해 빈칸을 채우는 방식이 가장 빠릅니다.
2. **확인** — `python -m factory.cli plan 주문서.yaml`
   템플릿과 색이 마음에 드는지, 무엇이 비어 있는지 짓기 전에 봅니다.
3. **짓기** — `python -m factory.cli build 주문서.yaml -o out/고객 --zip`
4. **채우기** — `out/고객/납품메모.md` 의 체크리스트를 고객과 함께 메웁니다.
   `[...]` 로 남은 자리가 전부 사라져야 납품할 수 있습니다.
5. **올리기** — 폴더를 Netlify 에 끌어다 놓거나 FTP 로 올립니다. 설정 파일은 이미 들어 있습니다.

여러 건은 `python -m factory.cli batch 주문서폴더 -o out` 로 한 번에 찍습니다.

## 알고 있는 한계

- **레퍼런스는 CSS 만 읽습니다.** 자바스크립트로 그리는 사이트(React 등)는 신호가 거의
  안 나옵니다. 이때는 `problems` 에 적히고 업종 기본값으로 갑니다 — 잘못된 것이 아닙니다.
- **구글 폰트는 인터넷이 있어야 보입니다.** 없으면 시스템 고딕으로 떨어집니다.
  본문 서체는 애초에 한글 폰트라 큰 차이는 없습니다.
- **문의폼은 받는 곳이 없습니다.** `--form-action` 으로 Formspree 같은 주소를 꽂아야
  실제로 메일이 옵니다. 안 꽂으면 폼 아래에 그렇게 적힙니다.
- **쪽수는 1과 5만 찍습니다.** 3쪽을 요청하면 가까운 쪽으로 맞추고 경고를 남깁니다.
- **사진은 그대로 복사만 합니다.** 크기를 줄이거나 webp 로 바꾸지 않습니다.
