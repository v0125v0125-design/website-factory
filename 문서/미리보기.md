# 미리보기 발행

고객에게 보여 줄 임시 주소를 만드는 방법입니다. **고객 도메인은 연결하지 않습니다.**

```
https://v0125v0125-design.github.io/website-factory/<고객 slug>/
```

| 주소 | 무엇 |
| --- | --- |
| `…/website-factory/` | 미리보기 목록 |
| `…/website-factory/gonggan-interior/` | 공간인테리어 (마스터 견본) |
| `…/website-factory/a-gonggan-interior/` | 고객 A (베이지) |
| `…/website-factory/b-onhouse/` | 고객 B (차콜 · 가운데 정렬 · 고른 격자) |
| `…/website-factory/c-asanhome/` | 고객 C (그린 · 카카오톡 없음) |

---

## 어떻게 올라가나

```
examples/customers/*.json ─→ tools/build_previews.py ─→ _site/<slug>/ ─→ gh-pages 브랜치 ─→ GitHub Pages
```

- **자동** — `main` 에 주문서·템플릿·엔진이 올라가면 `.github/workflows/preview.yml` 이 짓고 올립니다.
- **수동** — `tools/publish_preview.sh` 한 줄이 같은 일을 합니다.

`gh-pages` 브랜치는 **기계가 쓰는 곳**입니다. 손으로 고치지 마십시오 — 다음 배포에 덮어써집니다.

## 새 고객을 올릴 때

```bash
# 1. 주문서를 만든다 (examples/customers/a-gonggan.json 을 복사해 채우면 가장 빠릅니다)
cp examples/customers/a-gonggan.json examples/customers/d-새고객.json

# 2. 규격을 확인한다
python -m factory.cli validate examples/customers/d-새고객.json

# 3. 올린다 — 둘 중 하나
git add examples/customers/d-새고객.json && git commit -m "고객: 새고객" && git push   # 자동
tools/publish_preview.sh                                                              # 수동
```

`slug` 칸이 주소가 됩니다. 비우면 도메인이나 상호에서 만들어집니다.

## 다시 올리기

```bash
tools/publish_preview.sh                 # 전부 다시
tools/publish_preview.sh examples/customers/b-onhouse.json   # 한 곳만
```

GitHub Actions 쪽은 저장소의 **Actions → preview → Run workflow** 로도 돌릴 수 있습니다.

## 미리보기에만 있는 것

검수용 주소이므로 **검색에 잡히지 않게** 두 가지를 더합니다. 템플릿은 건드리지 않습니다.

- 지어진 HTML 의 `<head>` 에 `<meta name="robots" content="noindex, nofollow">` 한 줄
- 사이트 뿌리에 `robots.txt` (`Disallow: /`)

고객 도메인에 실제로 올릴 때는 이 스크립트를 쓰지 않고, `factory.cli build` 가 낸
산출물 폴더를 그대로 올립니다. 그 폴더에는 위 두 가지가 없습니다.

## 알아 둘 것

- 첫 배포 뒤 주소가 살아나기까지 30초쯤 걸립니다.
- 사진은 아직 저장소가 직접 그린 견본입니다. 고객 사진을 넣으면 `factory/images.py` 가
  역할별로 줄이고 WebP 로 바꿉니다.
- 견적 폼은 받는 곳이 없습니다. 실제로 받으려면 `--form-action` 으로 주소를 꽂습니다.

## 관리자 웹의 [미리보기 발행] 버튼

지금 구조가 그대로 그 버튼의 뒷면입니다.

```
[미리보기 발행] ─→ siteConfig 저장 ─→ factory.pipeline.build(brief, out/<slug>)
                                   ─→ _site/<slug>/ 로 복사
                                   ─→ gh-pages 에 푸시 (또는 정적 호스팅 API 호출)
                                   ─→ https://…/<slug>/ 을 화면에 띄움
```

`tools/publish_preview.sh` 가 하는 일을 관리자 웹이 대신 부르면 됩니다.
슬러그가 곧 주소이므로 고객을 늘려도 충돌하지 않습니다.
나중에 고객 수가 많아지면 브랜치 하나에 몰아넣는 대신
Cloudflare Pages 나 S3 같은 곳으로 옮기면 되는데, 바뀌는 것은 **마지막 한 줄(푸시)** 뿐입니다.
