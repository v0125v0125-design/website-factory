# MASTER_COMPANY_01

기업·B2B 마스터. **회사 신뢰도를 보여야 하는 법인**을 위한 판매용 원페이지입니다.

미리보기 → <https://v0125v0125-design.github.io/website-factory/company-01/>
(가상 기업 `브릭온테크` 견본 · 검색 노출 차단)

```

  partials/              머리 · 첫화면 · 개요 · 사업영역 · 핵심역량 · 제품 ·
```

## 1. 이 마스터로 파는 업종

제조 · 기계/장비 · 부품 · 설비 · 엔지니어링 · 건설 · 유통 · 물류 · 식품 제조 ·
산업 서비스 · B2B 서비스 · 일반 중소기업 · 법인 회사소개 · 스타트업

핵심 고객은 **"회사 신뢰도를 보여줄 홈페이지는 필요하지만 대형 구축까지는 필요 없는 기업"**
입니다. 업종을 바꿀 때 손대는 곳은 `services[]` · `projects[]` · `about` · `faq[]` ·
`seo` 다섯 군데뿐입니다.

### 가져온 원칙

- **첫 화면에서 업종을 바로 말한다.** 둘 다 "무엇을 하는 회사"를 한 줄로 못 박습니다.
- **사업 영역에 번호를 매긴다.** 세일정밀의 01~06 카드는 목차처럼 읽혀 담당자가 자기
  경우를 빨리 찾습니다.
- **국문·영문 상호를 병기한다.** B2B 거래처는 영문명으로 검색하는 일이 잦습니다.
- **회사 정보를 아래쪽에 충분히 준다.** 설립·대표·소재지·대응지역을 표로.
- **B2B CTA 는 과하지 않게.** 아진의 "무엇을 알려 주면 되는지" 안내형 접근은 좋습니다.

### 버린 원칙

- **10px 본문.** 담당자는 대개 40~60대입니다. 작은 글씨는 그 자체로 낡아 보입니다.
  이 마스터의 본문은 17px 에서 시작합니다.
- **히어로 자동 슬라이드.** 네 장이 도는 동안 아무도 읽지 못합니다. 한 장으로 고정합니다.
- **맥락 없는 숫자 배지.** `30+` `5+` `100%` 가 무엇의 수인지 화면에 없습니다.
  이 마스터는 **페이지에서 직접 셀 수 있는 것만** 숫자로 세웁니다(아래 참조).
- **파트너 로고 벽과 인증서 이미지 벽.** 가상 샘플에서 만들어 낼 수 없고, 실제 고객도
  자료를 줄 때만 넣어야 합니다. 자리는 만들되 비워 둡니다.
- **상단 메뉴 과다.** 원페이지 앵커가 아홉이라도 넓은 화면에는 다섯만 세웁니다.
- **떠 있는 상담 카드와 플로팅 레일.** 기업 홈페이지에서는 광고처럼 보입니다.

## 4. 섹션 차례

```
HEADER   국문+영문 상호 · 메뉴 5 · 대표번호 · 문의 버튼
HERO     무엇을 하는 회사 / 누구에게 / 사업영역 2×2 / CTA 2개
개요 띠   설립 · 사업영역 수 · 적용 산업 수 · 진행 단계 수   ← 첫 화면에 걸친다

수행 사례 표 — 적용 산업 / 프로젝트 / 수행 범위

회사 정보 대표 메시지 + 회사 개요 + 연혁 + 인증·보유설비
후기      받은 것이 있을 때만 (샘플에는 없음)
질문      FAQ
문의      B2B 폼 (회사명 · 담당자 · 연락처 · 분야 · 일정 · 요구사항)
FOOTER   바로가기 · 문의 · 오시는 길
```

## 5. 숫자를 만들지 않는 방법

개요 띠의 숫자는 **주문서에서 세어 만듭니다.**

| 칸 | 어디서 왔나 |
| --- | --- |
| 설립 | `company.founded` — 고객이 준 사실 |
| 사업 영역 N개 | `services[]` 길이 |
| 적용 산업 N개 | `projects[].분류` 의 서로 다른 값 수 |
| 진행 절차 N단계 | `process[]` 길이 |
| 대응 지역 | `seo.지역명` |

셀 것이 둘도 안 되면 띠가 통째로 빠집니다. "누적 고객 1,240곳"·"불량률 0.001%" 같은
숫자는 공장이 만들지 않습니다 — 확인할 길이 없기 때문입니다.
`test_the_overview_numbers_are_all_countable_on_the_page` 가 이걸 지킵니다.

## 6. 데이터가 어디로 가는가

| siteConfig | 화면 |
| --- | --- |
| `company.name` · `tagline` · `description` · `founded` · `owner` · `키워드[0]` | 머리(영문명) · 첫화면 · 개요 · 회사정보 · 바닥 |
| `hero.headline` · `subline` · `image` · `badges[]` | 첫 화면 |
| `services[]` (`name` · `설명` · `사진` · `항목[]` · `가격`) | 사업 영역 · 첫화면 2×2 · 개요 숫자 · 문의 폼 선택지 |
| `strengths[]` (`name` + `설명`) | 핵심 역량 — **`숫자`·`단위`는 쓰지 않습니다** |
| `gallery[]` | 제품 · 설비 |
| `projects[]` (`name` · `분류` · `설명` · `평형` · `사진`) | 수행 사례 표 · 개요의 적용 산업 수 |
| `process[]` | 진행 절차 · 개요의 단계 수 |
| `about.문단[]` · `사진` · `정보[]` · `연혁[]` · `인증[]` · `맺음` | 회사 정보 |
| `reviews[]` | 후기 (없으면 섹션이 빠집니다) |
| `faq[]` | 질문 |
| `contact.phone` · `address` · `hours` · `지도` | 머리 · 문의 · 바닥 |
| `seo.*` | `<title>` · 설명 · 공유 이미지 · 구조화 데이터 |
| `theme.preset` | `steel` · `graphite` · 그 밖의 기존 프리셋 |

**규격은 V1 그대로입니다.** 최상단 칸을 하나도 늘리지 않았습니다.
늘린 것은 `about` 블록 안의 선택 칸 둘뿐입니다.

| 새 칸 | 왜 |
| --- | --- |
| `about.history[]` / `연혁` | 기업 홈페이지에서 빠지지 않는 칸인데 기존 어느 칸으로도 표현되지 않습니다. `[["2018", "법인 설립"], …]` 꼴 |
| `about.credentials[]` / `인증` | ISO·특허·보유 설비. **가상 샘플에서는 비워 둡니다** — 만들어 내면 그 자리에서 거짓이 됩니다. 실제 고객이 자료를 주면 그때 섭니다 |

덤으로 **항목·값 목록을 읽는 방식을 고쳤습니다.** `[["항목", "값"], …]` 꼴을 예전에는
조용히 버렸습니다(인테리어·청소 견본의 `정보` 가 실제로 무시되고 있었습니다).
이제 사전 · 항목사전들 · 두 칸짜리 줄 세 가지를 모두 받습니다.

## 7. 관리자 웹에서 고객이 바꿀 칸

1. 상호(국문·영문) · 슬로건 · 회사 소개 · 설립연도 · 대표
2. 대표번호 · 소재지 · 영업시간 · 약도 링크
3. 사업 영역 3~5개 — 이름 · 설명 · 적용 분야 · 이미지 · 견적 표기
4. 핵심 역량 4개 — 제목 · 한 줄
5. 제품 · 설비 사진 4~6장
6. 수행 사례 6~10건 — 적용 산업 · 프로젝트명 · 한 줄 · 수행 범위 · 사진
7. 진행 절차 5~6단계
8. 회사 개요 표 · 연혁 · **인증·보유 설비**
9. FAQ
10. 색 버전 (`steel` · `graphite` …)

## 8. 고객에게 받을 사진

| 자리 | 장수 | 무엇을 |
| --- | --- | --- |
| 첫 화면 | 1장 | 라인·설비·공장 내부. 가로로 넓은 것 |
| 사업 영역 | **3~5장** | 영역마다 한 장. 그 일을 하고 있는 장면이 가장 좋습니다 |
| 제품 · 설비 | 4~6장 | 납품 제품, 보유 장비, 작업 장면 |
| 수행 사례 | 6~10장 | 작게 들어갑니다(64×48). 없어도 표는 그대로 섭니다 |
| 회사 | 1장 | 공장 외관 또는 조립·시운전 공간 |

**현장에서 알려드릴 말:** 발주처가 식별되는 로고·명판·제품 각인은 가려서 찍어 주십시오.
수행 사례에는 발주처명을 적지 않고 프로젝트 유형으로만 적습니다. 휴대폰 사진이면
충분하고, 세로·가로·저해상도·어두운 사진도 그대로 받습니다.

지금 견본에 들어 있는 그림은 **저작권 문제가 없도록 직접 그린 SVG** 입니다
(`tools/make_company_photos.py`). 라이선스를 확실히 확인할 수 없어 스톡 사진은
내려받지 않았습니다.
